# 夾取姿態與倒爪玩法規格

## 目標與假設

- 維持現有手機搖桿、桌機鍵盤與單次出爪流程；不增加「自動倒爪」按鈕。
- 正面瞄準時可正常夾取；偏向娃娃肩側下爪時，夾爪可因接觸而傾斜，讓兩爪從側下方承托。
- 倒爪是有條件的技巧，不保證成功；偏得太遠仍會落空。
- 成功搬運時娃娃跟隨夾爪的實際姿態，不在閉合瞬間吸到中心，也不讓模型明顯互穿。

## 技術與範圍

- 使用既有 Three.js 模型、Rapier 剛體與 Vitest，不新增依賴或素材。
- 修改夾爪碰撞／抓取評估、搬運姿態和必要的提示文字；不改投幣、稱號或整體 UI。
- 倒爪以側邊瞄準、下降時的物理接觸和有限傾斜觸發；本版不模擬保夾或真實機台機率表。每次開始挑戰時等機率抽選四檔握力（原力度的 100%、92%、84%、76%），該次挑戰的出爪與二收沿用同一檔。

## 驗收

1. 正常夾取時，娃娃位置相對夾爪連續，三爪在頭部／肩側外圍，而不是穿過臉部。
2. 偏側瞄準有可見的爪頭傾倒、兩爪承托和不同於正抓的抓取判定；偏移過大仍失敗。
3. 成功抓取至洞口、放開、掉落的完整流程仍可完成。
4. 手機與桌機瀏覽器沒有新增錯誤，測試與建置通過。

## 驗證指令

`npm test -- --run`、`npm run build`，並在本地瀏覽器做手機／桌機視角與完整夾取流程檢查。

## 深度辨識與回程平衡

- 初始擺位需在全體剛體自然靜止後，仍能讓夾爪中心直接對準前後排娃娃；不能只驗證擺入場景前的座標。
- 回程依移動距離給予 1.4–2.8 秒，夾力消耗按完成路程正規化，減少後排因固定高速回程而承受額外懲罰。
- 每次成功承托後產生有限的軌道震動時機、強度與方向。震動透過夾爪衝量、實際擺幅與夾力消耗影響搬運，不直接抽取成功或失敗。
- 弱夾會先出現爪口鬆開、娃娃下滑，再恢復物理掉落；穩固夾取仍能承受正常回程。回程前段保留自然擺動，最後接近洞口才逐漸減擺。

## 旋轉碰撞與脫爪

- 搬運採用受速度上限限制的動態跟隨，保留娃娃對機台、洞口擋板與其他娃娃的碰撞；搬運中亦保留夾爪碰撞，僅脱爪期間暫停爪片接觸解算。
- 妙蛙種子以模型頂點建立凸包，涵蓋頭部及背部種子。呆呆獸保留身體與突出尾部的複合碰撞。
- 被機台阻擋而偏離承托位置時，握力會額外衰減，避免娃娃被強制拖過障礙物。
- 正常放爪及途中滑落，均依模型旋轉後的最高點判斷是否已清空爪片，再恢復與夾爪碰撞。落入洞口前仍保留擋板碰撞。
- 店員可救援當局曾成功夾起、結束後確實停在洞口或夾爪旁的娃娃。已獲得的稱號不再重複顯示解鎖通知。
